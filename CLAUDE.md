# Sekel Desktop — Claude Notes

## Stack at a glance
- Electron 40 (electron-vite), React 19, TypeScript, Zustand, React Query
- Supabase (auth + Postgres + Storage), better-sqlite3 (local-first)
- Sentry for errors, i18next for i18n (5 locales), Vitest + Playwright

## Repo layout (npm workspaces + Turbo)
- `apps/desktop` — Electron app (main / preload / renderer split)
- `packages/db` — Supabase types + queries (`@sekel/db`)
- `packages/components` — Shared UI (`@sekel/components`)
- `packages/observability` — Logging / Sentry helpers (`@sekel/observability`)

## Commands
- Root: `npm run dev | build | lint | typecheck | test` (Turbo fan-out)
- Desktop renderer only: `npm run dev:renderer` (Vite, no Electron)
- Tests: `npm test` (vitest run), `npm run test:e2e` (Playwright)
- DB: `npm run db:push` to apply migrations to remote Supabase
- Version bump: `npm run bump` (root), drives the release pipeline

## Conventions
- 4-space indent in TS/TSX (matches existing files)
- Migrations: `apps/desktop/supabase/migrations/YYYYMMDDHHMMSS_name.sql`
  - Adding a column = write migration → update `packages/db/src/types.ts` → `npm run db:push` against the right project before the new field is usable
- DB queries belong in `packages/db/src/queries/<table>.ts`, exported via `packages/db/src/queries/index.ts`
- IPC: handlers in `apps/desktop/src/ipc/`, exposed through `contextBridge` in `preload.ts`, called as `window.electronAPI.*`
- i18n: any new key must land in all five locales (`en`, `de`, `es`, `fr`, `zh`) under `apps/desktop/src/locales/<lang>/translation.json`
- Sentry init lives in three processes — `main.ts`, `preload.ts`, `renderer.tsx` — keep them in sync

## Feedback submissions

User feedback rows get a sequential, human-friendly display ID separate from Linear tickets:

- Format: `Feedback-NNN` (zero-padded to 3 digits — `Feedback-001`, `Feedback-042`)
- Generated by the `ticket_number` `bigserial` column on `public.feedback`
- Used in Discord notifications and any internal triage workflow
- This is **not** a branch-naming convention — branches still follow `SEKEL-<NNN>-<description>`

## Branch & tag naming

- **Long-lived**: `main` (release target), `dev` (integration; default working branch)
- **Work branches**: `SEKEL-<NNN>-<kebab-description>` — Linear ticket first, then short description
  - Examples: `SEKEL-121-feedback-form-triage`, `SEKEL-119-remove-decks-empty-emoji`
  - No type prefix (`feature/`, `fix/`, etc.) — the ticket classifies the work
  - Kebab-case, lowercase, hyphens only, ≤ 50 chars
- **Release branches**: `release/v<X.Y.Z>` (e.g. `release/v1.0.6`) — the lone exception, version-tied
- **Tags**: annotated, `v<X.Y.Z>` — `git tag -a v1.0.6 -m "Release v1.0.6"`

Work flow: branch from `dev` → PR back to `dev`. Release flow: `dev` → `release/v*` → merge to `main` + tag.

Full reference: `.claude/skills/github-workflows/references/naming-conventions.md`.
